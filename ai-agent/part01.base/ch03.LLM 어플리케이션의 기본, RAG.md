# 01. RAG의 원리와 장단점

## LLM은 최신 정보에 대해서는 환각현상(할루시네이션)을 일으킨다.
LLM은 사전학습된 데이터를 기반으로 답변하기 때문에, 최신 정보에 대해서는 환각현상을 일으킴.

## LLM의 환각현상은 일종의 본질적인 현상.
LLM은 훈련 데이터 대한 흐릿한 기억을 바탕으로 새로 상상(생성)한다. 즉, 환각은 기본 작동 방식의 일부일 뿐 이를 극봅ㄱ하기 위한 방법으로 RAG가 있다.

## 트랜스포머라는 모델은 단순히 다음 단어를 예측하는 기계
LLM의 근간이 되는 트랜스포머라는 딥러닝 모델은, 입력받은 문장의 다음 단어로 무엇이 올지 예측하는 단어 예측 기계

## RAG는 LLM이 모르는 정보에 대한 답지를 주고 대답하게 만드는 시스템
RAG는 질문에 답할 수 있는 힌트를 더해 LLM에게 전달하는 방법론으로 주어진 사실에 근거하여 답변하기 때문에 환각현상 감소.
필요한 정보(텍스트)를 숫자로 저장해두었다가, 사용자의 질문에 답할만한 텍스트를 검색하여 LLM에 전달하고 생성하는 방식.

## 좋은 RAG 시스템을 구축하기 위해서는 다양한 요소를 고려해야 함
RAG 파이프라인 구축을 위해서는 다양한 컴포넌트를 활용해야하는데 이때 Langchain이나 Langgraph를 주로 사용.

문서 불러오기 -> 문서 임베딩 -> 벡터 DB 저장
- Closed Source LLM
- Open Source LLM

# 02. RAG의 한계를 극복하기 위한 Advanced RAG

## Naive RAG의 문제점은 매우 다양한 방법으로 해결 시도가 이뤄지고 있음
사용자 질문 구체화, 문서 파싱, 구조적 청킹, 리랭킹 등 다양한 모듈을 추가하여 검색 성능 향상하는 Advanced RAG 발전.
- 사용자의 질문을 더 상세하게 만드는 Query Rewrite 모듈
- 검색된 문서들을 한번 더 정렬/필터링하는 Rerank 모듈
- 문서 내 테이블/차트 등의 요소까지 인식한 정보 추출
- 문서의 구조를 고려하여, 최대한 맥락을 유지시켜주는 인덱싱 방법

## RAG 파이프라인의 각 과정을 개선하는 Modular RAG의 중요성 대두
질문이 왔을 때, 판단하는 모듈을 넣기

## 최선의 청킹 전략은 내가 가진 문서의 특성에 알맞게 실험하여 얻어짐
청킹이란? AI가 이해할 수 있는 문맥 단위로 문서를 분리하는 과정 (검색 정밀도 향상)

잘못된 청킹의 문제점 -> 맥락 단절, 정보 희석, 검색 효율 저하

실증 데이터 검증 -> 문서 유형별 최적 크기

청킹 전략 비교 및 추천
- 고정 크기
- 의미 기반
- 재귀적
- 적응형

## 적은 정보를 담은 쿼리를 확장하여 검색 성능을 향상시키는 것은 필수

Pre-Retrieval: 사용자의 원본 질의(Query)를 검색에 적합한 형태로 가공하는 단계
- Query Transformation: 질의의 표현을 바꾸되, 의미는 유지하는 작업
- Query Expansion: 질의에 관련된 단어·개념을 추가하여 검색 범위를 넓힘
- Query Construction: 실제 검색 엔진에 전달할 “최종 쿼리”를 구성하는 단계

## 검색기를 다양하게 구성하여 검색 결과의 정확성을 올릴 수 있음

Retrieval: Pre-Retrieval에서 가공된 쿼리를 사용해 지식 저장소로부터 관련 문서를 실제로 가져오는 단계
- Retriever FT: Retriever 자체를 특정 도메인에 맞게 학습(Fine-tuning) 하는 것
- Retriever Source: Retriever가 접근하는 실제 데이터 출처
- Retriever Selection: 질의(Query)에 따라 어떤 Retriever를 사용할지 결정

- Multi-retriever: 여러 Retriever를 병렬로 실행하여 결과를 모음
- Hybrid-retriever: 서로 다른 검색 방식(Keyword + Vector)을 결합

## 최대한 관련된 문맥만 LLM에게 전달하기 위해 Reranking 수행 필요

Post-Retriever: Retriever가 가져온 다수의 문서/청크를 LLM에 전달하기 직전, “정제·축약·선별”하는 단계
- Rerank: Retriever 결과의 “관련도 순서”를 다시 매기는 작업
- Compression: 문서의 “불필요한 부분”을 제거하거나 요약
- Selection: LLM에 실제로 넘길 문서/청크를 최종 결정

1. 문제 정의: RAG의 정보 손실
2. 해결 전략: Reranking(순위 재정렬) 도입
3. 방법론: Reranker 통합 및 파인튜닝
4. 평가: 성능 체크 & 효과 검증
